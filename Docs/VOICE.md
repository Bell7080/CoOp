# 근접 음성 / 무전 음성 설계

상태: **게임 상태 쪽(누가 어떤 경로로 송신 중인지)만 구현했다. 마이크 캡처·전송·재생은 아직 구현하지 않았다.** 이 문서는 이미 소리가 난다는 의미가 아니다.

## ElecMole 무전 규칙 (v0.4.0, 게임 상태만)

- E를 누르고 있는 동안 송신한다(`PlayerRadio.Mode`, 방장 기록).
  - 밖에서: 무전기를 들어 올린다(`Walkie`). 우주선 안 플레이어에게 우주선 스피커로 들린다.
  - 우주선 안 방송 마이크(`ShipMic`)를 보고: `ShipMic`. 모든 플레이어에게 이어폰처럼 들린다.
- 가까운 거리(`VoiceRouting.ProximityRange`, 18m)는 근접 음성. 죽은 플레이어(유령)는 산 사람을 듣지만 아무도 유령을 듣지 못한다.
- 청취 판단은 `VoiceRouting.HearsNearby` / `HearsOverRadio`에 모았다. 나중에 붙일 음성 제공자는 이 함수로 누구에게 어떤 효과(근접 3D / 스피커 / 이어폰)로 재생할지 정한다.
- 지금은 송신 시작·끝에 딸깍 소리와 HUD 표시(송신 중, 수신 중)만 있다.

## 경계

- NGO: 플레이어, 위치, 생존 상태, 소지 무전기, 채널·전원·배터리 등 게임 상태.
- `IRoomGateway`: 방과 연결. 현재 개발용 Relay, 이후 Steam용 방/전송 구현.
- 음성 전송 제공자: 마이크 캡처, 코덱, 패킷 전송, 지터 버퍼, 재생. 게임 상태 RPC에 원시 PCM을 싣지 않는다.
- 청취 정책: 거리 감쇠, 벽 차단, 무전 채널, 음소거, 죽은 플레이어 청취 규칙. 음성 제공자의 종류와 분리한다.

Steam 출시를 고려하더라도 Steam Voice API만 연결하면 근접/무전 전체가 자동 구현되는 것은 아니다. 코덱·전송·버퍼·오디오 재생과 매핑이 필요하다. 개발 중에는 Vivox 위치 채널/그룹 채널도 대안이지만 서비스 활성화와 실제 마이크 테스트는 별도 작업으로 진행한다. 아직 제공자를 확정하거나 패키지를 설치하지 않았다.

## 근접 음성 요구사항

- 각 청자의 관점에서 말하는 플레이어 위치에 3D 음원을 배치한다.
- 거리 감쇠 곡선, 들리기 시작/끝나는 거리, 벽·문 감쇠는 설정 데이터로 관리한다.
- 플레이어 위치는 NGO 상태에서, 오디오 렌더링은 로컬에서 처리한다.
- 최대 거리 밖에서는 받지 않거나 음소거한다. 단순 클라이언트 볼륨 0은 비밀 유지 보장이 아니므로 스텔스/사망 규칙이 중요하면 전달 대상도 서버/서비스에서 제한한다.
- 마이크 장치 선택, 입력 레벨, PTT/음성 감지, 개별 음소거, 출력 볼륨을 제공한다.

## 무전 요구사항

- 송신자·수신자 모두 무전기 소유, 전원 ON, 같은 채널, 생존/게임 규칙 허용 상태여야 한다.
- 무전 송신 버튼을 누르는 동안만 전송한다. 배터리와 채널 변경은 방장이 검증한다.
- 가까이 있는 같은 사람의 음성이 근접/무전으로 중복 재생되지 않도록 우선순위를 정한다.
- 무전 음성은 거리보다 채널 기반으로 전달하고, 로컬에서 필터·압축·노이즈·송신/수신 효과를 적용한다.
- 음성 대화 자체를 적 AI가 들을 경우, 신뢰할 수 없는 클라이언트의 “음량”만으로 판정하지 않는다. 게임 규칙용 소리 이벤트와 마이크 전송을 구분한다.

## 검증 계획

두 실제 PC와 헤드셋으로 근접→멀어짐→벽/닫힌 문→무전 채널 변경→음소거→퇴장/재입장을 확인한다. 2인부터 시작해 6인 동시 대화, PTT 중첩, 지연·손실, 장치 변경, 마이크 권한 거절도 검사한다. 실제 마이크 테스트 전까지 완료로 표시하지 않는다.

개인 음성 녹음이나 전사 기능은 기본으로 추가하지 않는다. 사용자가 요청한 음성 통신 범위에서 구현한다.
